## Task

`skills/plan/scripts/plan.py` and its template, as research 0004's Findings "The plan skill" lists them (plan 0015
D6-D9, plan 0016 D5, D6):

- **Columns**: `read_steps` reads `Window` and `Size`; in a record-format plan every row names its own Model,
  Effort and Window (no fallback to `run`); a legacy plan keeps the `Run:` fallback.
- **`run`**: `run: <model> <effort> <window>` is the coordinator's (`run_default` stays the legacy step default).
- **The check** (`plan-steps-sized`, in `run_check` beside hal2's records checker, one line per problem ending in
  its rule): the open rows of record-format plans need Model in `haiku|sonnet|opus|fable`, Effort in
  `low|medium|high|xhigh|max`, Window `200k|1m`, Size `<n>k`/`<n>m` at most 35% of Window; `run` needs three valid
  words. Done rows and legacy plans pass. `plan.py current` lists the same problems in `problems`.
- **`plan.py run [--sync | --check | --model m --effort e --window w] [--plan <slug>]`**: `--sync` writes the
  session's live values (`session.py`) into `run`; `--check` prints `{"run", "live", "drift"}` (`context.drift`),
  exit 0; explicit values set them.
- **`new`** writes the live values into `run` (fallback: the template's), the template's table gets the columns
  `| # | Step | Done when | Model | Effort | Window | Size | Status |` and its sentence says what they mean.
- **`plan.py migrate [--plan <slug>]`**: a record plan without the columns gets them; open rows' Model and Effort
  from the old two-word `run` when empty, Window from the model (`1m` for 5.x), Size `?` (the check reports it until
  estimated); `run` gets the live values. Never touches a legacy plan or a done row.
- Not here: `plan.py prompt` and parallel.py (step 3), SKILL.md (step 4).

Done when: unittest passes; `plan.py check` refuses a fixture plan whose open row lacks Window
