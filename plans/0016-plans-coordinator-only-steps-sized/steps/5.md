## Task

findings/handoff-grill.md items 3-4 and "Tests to add"; plan 0015 D10, D11, D16; plan 0016 D8). `plan.py run
--check` exits 0 always and names differences in its `drift` (step 2's Notes); `run --sync` writes the live values.

- **Write**: a new "### 3b. Persist the coordinator's values" before the handoff is stamped: `plan.py run --sync`
  for a plan with `run` (not in a slot with plans/LEAD, where plan.py refuses it); plan.md joins step 5's commit list.
- **Continue**: a new step 0 before step 1, never preceded by a `--sync`: compare `run` with the live session; on a
  model or effort drift, `hal2-cli-agents switch --model <run's model> --effort <run's effort> --prompt "/handoff
  c" --detach --json` and end the turn with one line; the loop guard: a drift for the same handoff (`at`) after a
  switch already ran gives `run --sync` instead (the session's values win, said in the first report); a refused
  switch (no hal2, not in a pane): go on and name it under Watch out. No plan, no `run`, or a window-only drift:
  nothing to do.
- **Deterministic first** (CLAUDE.md): a script in `skills/handoff/scripts/` (e.g. `drift.py`) decides step 0 and
  prints `{action: ok|switch|sync, command, run, live, why}`; it records a switch it hands out under
  `~/skills/handoff/switches/` (`HANDOFF_ROOT` overrides the root; the repo's skill data rule) keyed by checkout and
  `at`, so the guard needs no judgment. It also gives `/handoff clear` its effort.
- **Clear and continue**: `hal2-cli-agents clear-and-continue --effort <run's effort> --detach --json` (D8; no `run`:
  without `--effort`).
- Tests (`skills/handoff/scripts`): drift found on a record plan with a faked session (fixture transcript or env,
  never the real session), switch once then sync for the same `at`, legacy `Run:` and no plan give ok; `run --sync`
  plus `commit-handoff.sh` with plan.md commits the new `run`; a SKILL.md order test (step 0 before any `--sync` in
