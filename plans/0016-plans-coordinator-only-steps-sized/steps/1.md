# Step 1: session.py, the session's live model, effort and window; context.py uses it

<!-- Short and concise: at most 120 lines; link the research, records and code instead of repeating them. -->

## Task

A new `skills/plan/scripts/session.py` (D4) reads the running Claude Code session's live values, each with its
source, deterministically (research 0004, Findings "The plan skill" and "Handoff and grill"; plan 0015 D10, D16):

- **model**: the transcript's last main-chain `requestedModel` (carries `[1m]` when asked for), else the last
  `/model` switch ("Set model to ..."), else the `claude` process's `--model`, else `$ANTHROPIC_MODEL`, else
  settings.json `model` (context.py's `session_model` holds most of it: move it here).
- **effort**: the last main-chain assistant entry's `effort`, else `$CLAUDE_EFFORT`, else the transcript's
  "Set effort level to <e>", else the process's `--effort`, else settings (`effortLevel`,
  `modelSettings.<id>.effortLevel`).
- **window**: `$CLAUDE_CONTEXT_WINDOW`, else `[1m]` or "1M context" in the model, else a 5.x model (`opus`,
  `sonnet`, `haiku` and `claude-*-5-*` ids) is 1m unless `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`, else 200k; more
  tokens used than 200k means 1m (context.py's rule).
- CLI: `session.py [--transcript <file>]` prints `{"model", "effort", "window", "sources": {...}}` (window as
  `200k`/`1m` and in tokens). context.py takes its window from it, adds `model` and `effort` to its JSON and
  `drift`: the fields where the session differs from the current plan's `run: <model> <effort> <window>`
  (plans/CURRENT_PLAN, front matter `run`; a model compares by family without `[1m]`; no plan or no `run`: `{}`).
- Tests: `test_session.py` (each source and its fallback, scripted transcripts and env), `test_context.py` updated.

Done when: `python3 -m unittest discover -s skills/plan/scripts` passes; `context.py` here shows window 1000000 and
effort max
